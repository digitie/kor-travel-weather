# API 메트릭 수집 지연 격리

/metrics는 비동기 endpoint지만 mmap 파일 검사·병합·직렬화를 동기 호출했다.
이 수집이 느리면 같은 이벤트 루프의 /health와 다른 요청까지 대기한다.
수집 함수만 기존 thread pool에서 실행하도록 바꾸어 요청 처리 루프와 분리했다.
인증 순서, 수집 payload, 파티션 gauge, 실패 응답·비공개 캐시 헤더는 유지한다.

회귀 검사는 같은 TestClient 이벤트 루프에서 메트릭 수집을 명시적으로 대기시킨다.
수정 전에는 병행 /health가 0.5초 예산을 넘는다. 수정 후에는 수집을 해제하기 전에
생존 응답이 성공하며, 해제 후 원래 수집 payload가 반환되어야 한다.
제한 시간으로 대기 신호와 두 요청을 정리하므로 실패해도 테스트가 영구 정지하지 않는다.

운영의 위치 목록 504 원인을 이 코드 하나로 확정하지 않는다.
해당 운영 장애에서 메트릭 수집이 실행 중이었는지는 아직 확인하지 않았다.
이 변경은 재현한 이벤트 루프 전파 문제를 고치며, DB 대기·수집 작업의 CPU 비용과
서버 자원 압박은 별도 실측 대상이다. 운영 CPU·메모리 감소나 live UI 성공은 배포 뒤 확인한다.
