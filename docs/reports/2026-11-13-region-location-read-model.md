# 저배율 대표 위치 읽기 모델

## 문제와 변경

지도는 전체 위치 카탈로그의 모든 페이지가 끝나야 지역 대표를 계산했다. 시도·시군구 지도에
실제로 필요한 지점 수보다 많은 위치와 저장 역주소를 매번 읽던 초기 경로를 분리한다.

`0040_region_locations`는 재생성 가능한 `weather_region_locations`와
`weather_region_projection_states`를 추가한다. 첫 테이블은 지역별 실제 지점 ID·라벨·주소 좌표 키·
위치 수정 시각·멤버 수만 저장한다. 기상 원본이나 영구 통계를 복제·삭제하지 않으며 기온·기상 코드를
평균내지 않는다. 지역 중심에 가장 가까운 실제 지점을 고르고 동률은 ID로 결정한다.

KMA 일반 날씨 publication이 성공한 뒤 저장 주소로 갱신한다. 특보 전용 수집은 갱신하지 않는다.
캐시 writer끼리만 비대기 advisory lock으로 합치며, 잠금이 바쁘면 기존 게시본을 유지한다.
캐시의 행과 상태는 한 transaction으로 교체한다. 갱신 실패는 별도 metadata·로그에 남기고
이미 성공한 기상 수집을 실패로 뒤집거나 외부 재수집을 시작하지 않는다.

## 읽기 계약

`GET /v1/weather/regions`는 `ready`, `calculated_at`, `items`를 반환한다.
각 항목은 `level`(sido/sigungu), 지역 키·라벨·멤버 수, 공개 `LocationOut`이다.
대표의 위치가 비활성화되거나 수정 시각·저장 주소 키·소속이 맞지 않으면 `ready=false`와 빈 항목으로
전체 카탈로그 fallback을 요구한다. 상태와 참조는 같은 REPEATABLE READ snapshot에서 읽는다.
반환 상한은1000개이며 기상 fact나 전체 위치 metadata를 읽지 않는다. OpenAPI와 TS 타입도 함께 갱신했다.

`calculated_at`은 마지막 대표 참조 계산 시각이며 기상 관측 시각이 아니다. 멤버 수 역시 그 계산
집합 기준이다. 이 API가 모든 위치 변경의 즉시 집계를 보장하지 않는다. 실제 날씨는 기존 마커 API로
읽어 원천 시각·특보·종류·제공처 규칙을 유지한다.

## 화면 경계

전역 대표는 전체 카탈로그를 기다리거나 전체 조회가 실패한 동안의 무검색·무제공처/종류 필터
저배율 지도에만 쓴다. 전체 목록 실패 시 오류 안내와 함께 사용 가능한 대표 지도·선택 상세를 유지한다.
캐시 조회와 전체 목록 조회를 병행하며, 캐시의 실패·미준비는 전체 목록을 막지 않는다.
검색·필터·상세 축척 또는 전체 목록 완료 후에는 기존 집합의 대표/클러스터 경로를 사용한다.
전체 목록 도착만으로 이미 탐색한 대표 지도의 카메라를 되돌리지 않는다.
