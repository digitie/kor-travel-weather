# 선택한 날씨 지역의 실제 경계

## 소비 경로

지도에서 날씨를 선택하면 선택 당시의 축척으로 시도·시군구·읍면동·리 단계를 고정한다.
Geo의 기존 `/v2/reverse`에서 실제 위치의 법정 코드를 얻고 `/v2/search`의 district·geometry를
조회한다. Geo Python `AsyncAddressClient`는 Geo DB를 직접 소유하는 facade이므로 Weather에
Geo DB 접근이나 provider 파싱을 복제하지 않고 기존 서비스의 공개 HTTP 계약을 소비한다.
Weather의 `region_code`는 기상 예보 코드이며 법정 코드로 사용하지 않는다.

실제 지역 Polygon/MultiPolygon·EPSG:4326·단계별 원천 테이블·일치 코드가 모두 확인된
단일 후보만 사용한다. 좌표·닫힌 ring·정점 수를 검산하고 bbox는 실제 도형으로 계산한다.
읍면동 코드의 리 접미00을 리로 표시하거나 사각형 bbox를 실제 경계로 대신 그리지 않는다.
자료 없음·모호한 후보·다른 제공처·다른 단계는 경계 미확인으로 안내한다.

Geo 원 경계는 이미 Geo DB에 저장되어 있다. Weather의 새 DB 복제나 수집 작업 대신
BFF 메모리 캐시를 최대128개·16MiB·6시간으로 제한한다. 원천 요청은 총8초·응답4MiB·동시4개로
제한하고 브라우저 취소를 전달한다. 키는 서버 `X-KTG-API-Key` 헤더에만 넣으며 URL·오류 원문·
브라우저 응답·Git에 기록하지 않는다. 기존 session-only middleware가 이 경로도 보호한다.

## 화면과 카메라

경계 채움·외곽선을 지도에 표시하고 실제 상세 패널 영역을 측정해 PC 오른쪽/모바일 위쪽
여백을 남겨 맞춘다. 모바일에서는 경계 표시 중 패널을 지도 높이42%로 제한해 도형을 볼 공간을 남긴다.
선택 후 사용자가 지도를 조작하면 늦은 응답이 카메라를 되돌리지 않는다. 다른 선택·패널 닫기·
목록 전환 시 이전 요청과 레이어를 정리한다. 스타일 변경 시 경계만 복원하며 다시 확대하지 않는다.
측정 지점·위치 이동 버튼의 명시적 이동은 진행 중인 경계 이동보다 우선한다.

## 설정과 수용 경계

- 배포 담당은 웹 서버의 `WEATHER_GEO_INTERNAL_URL`과 `WEATHER_GEO_API_KEY`를 비공개 환경으로
  제공해야 한다. 미설정이면 경계 미연결 안내를 표시하며 기존 날씨·지도 기능을 유지한다.
- Geo의 로컬 실제 자료가 없는 구역은 자동 외부 수집이나 가짜 도형으로 채우지 않는다.
- 이 작업은 소스·fixture 테스트·머지 범위다. 실제 Geo 연결·키 설정·전국 경계 보유량·실화면·
  이미지 빌드·배포는 아직 수용하지 않았다. KMA/기존 수집 일정·운영 DB·키 변경은 없다.
