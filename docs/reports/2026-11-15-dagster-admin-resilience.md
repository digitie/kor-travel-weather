# Dagster 상세·운영 액션과 수집 회복 경계

## 관리자 화면

모든 실행 상태에서 선택한 실행의 단계·시도·시각·처리 건수와 안전한 원인·복구 지침을 확인한다. 이벤트는 선택할 때 200개씩 읽고 더 보기는 cursor로 이어간다. 목록에서 모든 과거 로그를 미리 조회하지 않는다. 통계가 미확인이면 0으로 만들지 않는다.

작업의 기본 설정 실행, 실패·취소된 같은 작업의 현재 기본 설정 재실행, 정상 취소, 일정·센서 시작/중지를 제공한다. 실패 단계만 이어받는 기능으로 표시하지 않는다. 실제 서버 기능·권한·현재 상태를 다시 확인하고 해당 앱 위치·저장소의 실행만 다룬다. 이미 같은 작업이 진행 중이면 기존 실행을 보여준다.

고정 `/api/dagster/console` 요청만 허용한다. 기존 로그인·세션·origin 검사와 응답 크기·시간 상한을 유지하고 임의 GraphQL·설정·태그 입력은 받지 않는다. 실패 원문·URL·비밀값·임의 태그는 브라우저로 내보내지 않는다. 결과가 불명확한 실행 요청은 새 요청으로 자동 재전송하지 않는다. 같은 요청 ID의 상태를 먼저 확인하고, 명시적인 같은 요청 확인·복구만 제공한다. 앱 위치별 요청 ID를 분리하며 반환 실행의 소속도 검산한다.

공용 서버의 실제 GraphQL 문서 12개는 전체 문서를 검증하되 별도 `__typename` 연산만 선택하는 읽기 전용 방식으로 확인했다. 운영 mutation 실행은 0회다. 실제 운영 액션의 실행 수용은 배포 담당의 후속이며 모의 요청 시험과 구분한다.

## 성공과 부분 미완료의 구분

Dagster의 `SUCCESS`는 실행 종료 상태다. 원천 전체의 최신 자료 확보를 뜻하지 않는다. `kortravel/collection-outcome`에는 `partial`·`deferred` 경고만 쓰며 뒤 정상 단계는 이를 지우지 않는다. 태그 기록 실패도 정상 저장을 실패시키지 않는다. 동시 경고끼리의 순서는 보장하지 않으며 각 단계 출력 metadata의 원 상태·처리 건수가 정본이다. 관리자 목록과 상세는 이 경고를 정상 전체 수집과 구분한다.

일시 장애 뒤 정상 자료를 저장했으면 그 자료를 유지하고 미완료 범위를 남긴다. 모든 원천 실패, 인증·일일 할당량, 저장소 연결 장애, 소유권 상실은 실제 실패로 보존한다. 오래된 자료의 기준 시각을 갱신하거나 빈 자료를 새 정상 수집으로 꾸미지 않는다. 새 전역 잠금·수집 큐·설정 토글·DB 스키마는 추가하지 않았다.

## 검증 범위

WSL과 Docker의 집중 검증·관리자 원본 소스의 PC1440/모바일375 fixture 검증을 수행한다. 공식 CI와 두 독립 검토의 최종 결과·머지 SHA는 이 문서가 포함된 PR 원장을 따른다. 이미지 빌드·운영 배포·실제 일정/수집 변경은 이번 작업에서 하지 않는다. 기존 외부 자료 미제공과 운영 신선도 수용을 소스 완료로 바꾸지 않는다.

## Weather 수집과 KMA 속도

한 격자의 SDK 재시도 소진·자료 없음·안전하게 격리 가능한 export DB 잠금 오류 뒤에도 정상 격자는 저장한다. 부분 commit은 DB 실행 계수로 종료해 실제 저장 건수가 유실되지 않으며 불완전 cohort는 최신 export로 승격하지 않는다. 구체적인 경계와 원 실패는 [격자 회복 검증](2026-11-15-kma-grid-resilience.md)에 남겼다.

KMA SDK [PR33](https://github.com/digitie/python-kma-api/pull/33)의 검증 제품 `ff80b74bdab507e642bf5deeaa7e89106943c4f4`를 고정한다. 공식 오류23은 기존 단일 HTTP 시도 예산·토큰·백오프에서 재시도하고 일일 오류22는 재시도하지 않는다. HTTP200의 작은 표준 JSON/XML 오류 봉투만 판별하며 정상 대용량 날씨 본문을 중복 해석하지 않는다. 앱의 별도 재시도 루프는 없다.

전담 rate 분석의 권고는 소스의 20회/초·선행 격자4개 유지다. 실제 운영 관측은 여전히 10회/초·2개이며 이 작업에서 바꾸지 않았다. 같은 metrics epoch에서 SDK 논리 호출 평균 span은 현재 관측 약0.095초, 초단기 예보0.291초, 단기예보2.721초다. 단기 예보의 선행4개 이론 상한은 약1.47논리 호출/초로, 상한만20 초과로 높일 근거가 없다. 정규화·위치 확장·저장·게시 비용을 함께 줄여야 한다. span에는 limiter·재시도·해석이 포함되고 병렬 시간이 겹치므로 순수 RTT나 전체 시간의 비율로 해석하지 않는다.

300격자의 기본 일정은 재시도·추가 페이지·다른 작업을 빼도 하루16,800논리 호출이다. [공식 안내](https://www.data.go.kr/data/15084084/openapi.do)의 개발 기본 트래픽과 실제 승인 계정 할당 범위는 다를 수 있으며 현재 계정의 범위는 미확인이다. SDK 제한기는 클라이언트별이므로 여러 작업의 합산20회를 보장하지 않는다. 따라서 20은 검증된 보편적 최적값이나 공식 TPS 한도라는 뜻이 아니다. 실제 계정 한도·오류23·토큰 대기·게시 비용을 보며 조정할 권고 상한이다. 외부 부하 시험은 하지 않았다.

SDK WSL/Docker 각306개(통합12개 제외), 격자109개, 제한 진단27개, 경고 태그16개를 각각 검증했다. 같은 시험과 환경을 합산하지 않는다. 최초 실패와 보정은 각 원장에 보존한다. 실제 새 SDK에서 앱 수집까지의 추가 회귀 결과는 PR에 별도로 정산한다.

새 SDK의 공개 `KmaClient`와 모의 HTTP 응답을 실제 Weather 격자·게시·asset에 연결한 추가4조건은 WSL/Docker 각각 통과했다. JSON/XML23 뒤 정상 응답은 HTTP2회로 원문·관측값을 각각1회만 저장했고,22는 HTTP1회·저장0,23 재시도 소진은 기존 예산의 HTTP3회·저장0과 정확한 scope/복구 지침을 확인했다. 저장 seam은 기존 FakeRepository이므로 이4조건을 실DB·운영 수용으로 확대하지 않는다. 원 사전 Git 경로 실패와 optional HTTP status 시험 가정 오류는 별도 보존했다.

관리자 집중 시험은 WSL·Docker 각각132개, 변경 ESLint·타입 검사도 통과했다. 원본 소스 Controls/Inspector/Warnings를 PC1440·모바일375에서 확인하고 overflow·pageerror·외부 요청0, 소유 브라우저·fixture 서버 잔여0을 검산했다. 화면 액션은 모의 서버에서만 시험했다.

실행 응답이 HTTP200이어도 본문이 손상되거나 action state가 누락되면 결과를 미확인으로 유지하도록 보강했다. 동일 요청 ID를 보존하고 새 실행을 자동 제출하지 않는다. 양 앱 각각 실제 RED12개 실패 후 WSL/Docker37개 통과를 확인했다. 최초 CI의 Doctor 경고4개(두 화면 함수 복잡도, 이벤트 재구독, 응답 상태 확인 순서)는 검사 설정을 완화하지 않고 소스 구조로 보정한다. 원 실패는 PR 원장에 남긴다.

최종 보정본은 전체 Doctor·변경 lint·타입 검사0, WSL/Docker 집중 각각129개를 확인했다. 앞선 시험과 합산하지 않는다. 고정 visibility 구독·최신 선택 실행 조회와 손상 응답 UNKNOWN을 보존하고, 격자 원인 JSON은4KB·허용5코드 정수만 표시한다. KMA 전체 격자 실패도 고정 원인으로 표시하며 임의 키·값·원문은 차단한다. 실제 소스 PC/mobile4캡처의 화면·동작 보존과 소유 프로세스 잔여0을 확인했다. native12문서도 Json fragment를 포함해 읽기 전용 재검증했다. 최종 소스 원장은 Git 밖 doctor-r3/receipt.json이다.

최초 전체 CI는 Python2030개 통과·2개 실패였다. 새 고정 GraphQL 문서는 기존 scope 정본으로 이동하고 검사 예외를 추가하지 않는다. 실패 후 API 회귀는 정확한 전체 격자 실패 타입을 확인하면서 원문·fact 건수, 정상 head, 기준 시각·옛 items·stale·ETag 보존을 강화했다. 실제 PG18의 인접5개는 WSL/Docker 각각 통과했고 제품 Python은 바꾸지 않았다. 최종 전체 CI는 별도로 정산하며 원 실패를 지우지 않는다.

문서 단일정본 보정은12문서의 내용과 태그·액션 조건을 그대로 유지한 이동이다. DB fixture가 없는 격리된 정적 검사 WSL/Docker 각각6개와 영향 Vitest 각각68개, 전체 Doctor·타입·lint를 확인했다. QA mirror와 소스 SHA도 전후 동일하다.

정적 계약의 첫 QA에서 앱 root conftest의 기본 로컬15432 DB fixture가 의도치 않게 로드됐다. 정확한 자기 pytest와 부모만 정상 종료·잔여0을 검산했으며 당시 로컬 시험 DB 영향은 미확인으로 보존한다. 현재 해당 포트의 Docker 게시/리스너0 관측을 과거 무영향 증거로 소급하지 않는다. 후속은 --noconftest와 DB fixture 부재 검산으로 분리했다. 운영 Odroid·서비스·DB 변경과는 별개이며 PG나 다른 프로세스에 종료 신호를 보내거나 복구 명령을 실행하지 않았다.
