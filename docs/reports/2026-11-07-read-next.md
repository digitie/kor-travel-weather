# Weather·Transport 추가 조회 개선

## 요청과 범위

사용자의 추가 개선·배포 요청으로 직전 세 회차 완료 뒤 남은 비용을 다시 측정했다. 신선도·좌표/가격 검증·소스 상태·cursor/예산을 유지하고 의존성/SDK/웹·스키마는 바꾸지 않는다. 기존 수집은 자연 종료를 기다리고 백업·복원 생략/새 독립 리뷰 중단 승인을 유지한다. 이 문서는 아직 새 이미지·배포 완료가 아니다.

## Transport — 장소 중첩 검증 한 번으로 구성

현재 제품aeff45/이미지791eb754의 별도 READ ONLY ASGI 프로파일은5,000곳7.36MB·18.85초(cProfile 포함)였다. SQL5개와 가격/장소 모델 CPU 비용을 구분했다. 5,000개 장소를 먼저 Pydantic으로 만든 뒤 부모에서 model-after 좌표 validator가 다시 실행돼 좌표 검증10,000호출이 관측됐다. fuel 지도 항목을 dict로 전달하고 부모의 같은 중첩 validator에서 한 번만 구성한다. 검증 생략/model_construct·새TTL·API필드 축소는 없다.

실제 ARM64/Pydantic2.13.4 고정5,000곳×5유종의3회 교대 국소 검산에서 CPU 중앙값1824.20→1491.21ms·wall4960.20→4270.22ms였다. ## Weather — 검산한 JSON 크기 재사용

불변 source plan을 읽을 때 개별/누적 JSON 예산에서 정규 UTF-8 크기를 계산한 뒤 cache 예산을 위해 같은 descriptor를 다시 encode했다. 검산 단계의 바이트 수를 parser cache에 함께 전달해 재계산을 제거한다. cache hit/miss의 합계와8MiB·단건256KiB 상한·행 존재 확인·원천/소유권·stale/TTL 정책은 그대로다. 한글·이스케이프/정확 경계·유실·초과·실제 공개 export 회귀40개가 WSL PG18·Docker PG18에서 각각 통과했다.

실제 source plan64개의 bounded sample을3,305개로 반복한 순수 예산 계산3회 교대에서 CPU369.23→192.36ms·wall1012.92→341.59ms였고 UTF-8 크기 배열 SHA a092f747eefada90b4f15801522b09f055fe0bcd436a705131776a83600d56c0가 같았다. 이는 반복 계산 국소 측정이며 current/daily HTTP 지연 개선율이 아니다.

## 관측 실패와 채택하지 않은 선택지

새 READ ONLY Weather freeze profile은 attempts SELECT에서 기존5초 상한/SQLSTATE57014로 중단됐다. timeout을 늘리거나 이를 정상 응답으로 바꾸지 않았다. 후속 읽기에서 활성 attempt6,452개의 owner_epochs 저장 크기는 합계471,711byte/최대74byte였고 얇은 조회0.87초·기존 열 포함1.08초였다. PK bitmap 경로·누적 통계만으로 큰JSON/잠금/인덱스 부재가 원인이라고 단정하거나 index/vacuum을 임의 추가하지 않는다.
