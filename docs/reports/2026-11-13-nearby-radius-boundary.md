# 반경 날씨 조회의 경계 누락 수정

기존 `GET /v1/weather/nearby`는 현재 위치·반경으로 현재 날씨와 예보를 조회한다.
반경 기본25km·최대500km, 최대100개 제한과 저장 DB의 좌표 인덱스 사전 필터,
정확한 Haversine 거리·정렬·LIMIT, 기존 배치 조회와 응답 예산을 유지한다.
추가 API·스키마·TTL·외부 수집·전체 위치 Python 정렬은 만들지 않았다.

## 재현과 변경

경도 범위를 각거리/cos(위도)로 근사하면 원의 동서 극값보다 작아진다.
합성 중심37N/126E·반경500km에서37.133369N/131.632523E는 실제499.9km지만
기존 사전 필터에서 제외됐다. 구면 원의 경도 극값 `asin(sin(각거리)/cos(위도))`를
사용하고 극점을 포함하는 경우 경도180도 범위를 사용한다. 최종 정확 거리 검사는 그대로다.

실제 저장소 SQL·실제 API 회귀2개는 수정 전 각각 경계 지점 누락으로 실패했다.
첫 시험의 API 응답 필드 접근 오류는 별도로 고친 뒤 재현했으며 제품 문제로 세지 않는다.
별도 PG18의 공식0040 마이그레이션 후 기존 반경·최근접·API 집중 시험은
WSL10PASS/Docker10PASS다. 같은 시험을 합산하지 않는다. Starlette의 기존 경고1개를 보존했다.
소유 시험 DB는 정확한 CID/label 검산 후 종료·제거했다.

James의 정적 리뷰에서 반경 밖 지점 제외 단정이 LIMIT2에 가린다는 시험 P2가 나왔다.
LIMIT3에서도 두 내부 지점만 남는 단정을 추가했고 수정된 SQL/API2개는 별도
PG18 WSL/Docker 각각2PASS다. 앞선10개와 겹치므로 합산하지 않는다.
제품 계산식·최종 필터 순서의 확정 P0/P1 지적은 없었다. 소스 lint도 통과했다.

원문은 Git 밖 작업 원장의 `weather-radius-red-r2-20261113`과
`weather-radius-green-20261113`이다. 이 수정은 거리 정확성 개선이며 실운영 속도·p95 개선의
새 증거가 아니다. 이미지 빌드·배포·운영 DB/환경/일정 변경은 없다.
