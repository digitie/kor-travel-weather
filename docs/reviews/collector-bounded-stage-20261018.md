# KMA 위치 단위 staging 상한 개선 후보

다음 위치를 추가하면 기존 staging 상한을 넘는 경우, 기존 묶음을 먼저 게시한다.
상한5000·위치별 원자성·source lineage·누적 예산·lease 검사와 재시도 경계는 유지한다.
한 위치 자체가 상한보다 큰 경우에는 해당 위치를 나누지 않는다.

같은 격자의10위치×792fact를 기존 방식으로 처리하면4752/792/2376의3회 게시가
발생한다. 후보는4752/3168의2회 게시를 목표로 한다. CPU/RSS 감소율은 아직 미측정이며
기본 batch 값을 줄이지 않는다. 기존 설정을2500/1000으로 줄인 격리 예비 실측은
메모리가 감소했지만 CPU가 증가해 채택하지 않았다.

게시 경계가 바뀌므로 실패 전 실제 commit 수는 달라질 수 있다.
예산7·위치당2fact·staging3 시험은 기존4개 대신2개가 commit된 뒤 실패하며,
run count는 실제 commit된2개를 유지한다. 나머지는 다음 정상 재수집으로 복구한다.
전체 작업의 원자성을 주장하지 않는다.

현재 검증: 새 격리 PostgreSQL에서 관련43 PASS, Ruff PASS.
초기 실행은 기본 로컬 시험 DB가 partition schema와 맞지 않아1실패/34통과였으며
해당 결과는 전체 통과가 아니다. 새 소유 PostgreSQL 환경에서 재검증했다.
이전 예산 시험의4개 기대값은 위 게시 경계 변경으로2개를 확인하도록 수정했다.
전체 회귀·실측·독립 리뷰2명·live UI·배포는 진행 전이다.
