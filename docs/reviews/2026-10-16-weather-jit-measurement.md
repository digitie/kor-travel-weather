# Weather PostgreSQL JIT 실측과 적용 판단

2026-10-16 운영 PostgreSQL 16.10에서 기존 예보 정리 후보 조회를 읽기 전용으로 비교했다.
고정한 동일 cutoff, LIMIT 1000, 동일 병렬 설정에서 JIT on → off → on → off 순서로 실행했다.
LLVM 사용 가능 상태이며 jit_above_cost는 100000이다. 전역 설정은 바꾸지 않았다.

| 차례 | JIT | 실행 시간(ms) | JIT 생성 시간(ms) |
| --- | --- | ---: | ---: |
| 1 | on | 1541.112 | 791.804 |
| 2 | off | 747.310 | 해당 없음 |
| 3 | on | 1734.828 | 844.642 |
| 4 | off | 778.493 | 해당 없음 |

JIT 사용 실행에서 59개 함수를 생성했고 생성 비용만 약 0.8초였다.
이 정리 조회는 두 번 모두 JIT를 끈 쪽이 빨랐다. 네 번의 진단 측정이므로
전체 시스템 CPU 개선이나 장시간 부하 시험을 입증하는 수치는 아니다.

지도 조회 계획의 추정 비용은 7000 미만으로 현재 JIT 임계값에 미달하며,
실제 계획에도 JIT가 없었다. 따라서 지도 지연을 해결하려고 JIT를 강제하지 않는다.
지도 조회는 SQL 구성의 캐시 재사용과 API의 중복 변환을 줄이는 개선을 별도로 검증한다.

정리 조회의 우선 개선은 0020_short_forecast_retention 부분 인덱스다.
실제 인덱스 적용 후 같은 조건의 실행 계획과 JIT on/off를 다시 비교한다.
필요한 경우 정리 트랜잭션에만 SET LOCAL jit = off를 적용하며,
측정 전 PostgreSQL 전역 JIT 설정을 바꾸지 않는다.
이 문서 작성 시점에는 운영 인덱스 적용 후 측정을 완료하지 않았다.

PostgreSQL 공식 문서도 JIT가 주로 오래 실행되는 CPU 중심 쿼리에 유리하고,
짧은 쿼리에서는 생성 비용이 절감 효과를 넘을 수 있다고 설명한다.
