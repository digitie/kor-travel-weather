# KMA 지도 수집 범위 개선

## 운영 기준과 구현 계획

2026-10-22 읽기 점검에서 활성 1,450곳 중 최근 24시간 일반 KMA 값 갱신은 258곳이었다. DB에 nx/ny가 저장된 389곳의 격자는 268개지만, 미계산 좌표를 python-kma-api의 public to_grid로 계산하면 전체 1,076개 격자다. 앞선 268개 전체 격자 설명을 정정한다. 명시 대상은 21격자다. 특보만 있는 위치도 기존 provider 존재 조건에 포함돼 필터 수는 1,450곳이었다.

고정 표본을 유지하면 누락 지역이 계속 누락된다. 기존 격자 중심의 공간 분산 순서를 보존하면서 실행에 고정된 시간 슬롯에 따라 수집 구간을 순환한다. 명시 대상 우선·비활성 제외·동일 격자 fan-out·기존 격자/행/값/flush 상한을 유지한다. 관측·초단기예보는 시간 슬롯, 단기예보는 3시간 슬롯을 쓴다. 실패/skip은 성공 coverage와 구분한다.

운영 fill 예산은 실측 후 확대하되 전체 300격자/회 상한은 유지한다. 정상 hourly 24회 기준 최대 7,200회/operation/day 계산에는 재시도·수동 실행·다른 소비자의 호출을 포함하지 않는다. 키별 실제 허용량을 보장하는 수치가 아니다. 전체 실시간 갱신 보장이 아니라 일정 주기로 전체를 방문하는 방식이다.

지도는 선택 제공처에 일반값이 있는 위치를 기본으로 조회하고, 특보만 있는 위치를 포함하는 옵션을 제공한다. API 기존 기본 동작을 유지하며 명시적인 weather_only 옵션에만 일반값 조건을 적용한다. provider와 일반값 조건은 같은 EXISTS 안에서 결합하고 페이지 제한 전에 실행한다. 특보 조회·표시는 유지한다.
