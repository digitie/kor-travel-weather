# 날씨 웹·Android/iOS 앱 조사와 현재 화면 대조

조사일 2026-10-25(KST). 조사·설계 문서이며 기능 구현·운영 검증 완료 보고가 아니다.
[Weather 변경 설계](../design/2026-10-25-weather-map-improvements.md)와 함께 읽는다.
교통·유가·철도·공항을 포함한 비교 조사 정본은
[Transport 조사](https://github.com/digitie/kor-travel-transport/blob/main/docs/research/2026-10-25-mobility-ux.md)다.

## 1. 사용자가 알고 싶은 질문

같은 ‘날씨’라도 지금 외출, 퇴근길, 내일 방문, 주말 여행, 산·해변 활동에서 필요한 시각·장소·요소가 다르다.
첫 답은 수집값 목록이 아니라 **선택한 장소의 해당 시간에 비·바람·기온·특보가 어떤지**다.
기존 `/weather`의 종류·장소·출처 필터와 지도/목록·상세 구조를 유지하면서 이 답에 먼저 접근하게 한다.
소비자처럼 조회하는 경험과 관리자의 기능 정상 확인을 함께 지원하며, 필요한 데이터가 부족하면 기존 API를 보완한다.
요청/응답/저장 상태 전용 패널을 모든 화면에 추가하는 요구가 아니다. 기존 API-test·수집 이력·Dagster 연결을 활용한다.

이 문서의 이용 상황은 공개 자료와 코드에서 도출한 설계 가설이다. 실제 사용자 인터뷰나 현장 사용성 시험을 수행한 결과는 아니다.

후기는 개별 경험이며 대표성·현재 버전 재현 여부를 확인하지 않았다. Android와 iOS 기능이 전부 같다고 추정하지 않는다.

|---|---|---|

관심 요소 순서·관심 장소·표/그래프 선호는 사용자 설정 후보다. 처음부터 목적별 여러 대시보드나
위험 점수·활동 추천 엔진을 만들지 않는다. 계정/즐겨찾기 등록 없이 저장 catalog를 검색하는 것과
DB 밖 목적지 이름을 좌표로 찾는 것은 다른 기능이다. 후자는 기존 Geo 계약/지도 지점 선택→저장 anchor의 대표성·부재를 설계에서 구분한다.
알림·백그라운드 위치·네이티브 위젯은 유사 앱의 기능이지 이번 웹 admin에 자동 추가할 범위가 아니다.

## 4. 현재 코드와 불일치·빈틈

기준 소스는 Weather `d4e5aa2801bf041ff9a28933d3d397d2df777e39`다. Map 기준은 `origin/main@c06345841`,
Common은 PR45 계열 지도 컴포넌트다. 다른 작업자의 Map/Common 미커밋 변경을 기준으로 사용하지 않았다.
Weather 운영 `/weather`는 로그인 리다이렉트까지만 확인했으므로 실제 배포 버전·치수·응답은 미측정이다.

초단기·단기·중기 예보는 시간 해상도와 공간 단위가 다르다. 기존 `latest` 값과 미래값을 분리한 변경은 보존한다.
특보 유효기간·해제·지역 범위, 예보 발표본과 target 시각, 관측 station 거리/시각은 각각 다른 의미다.
마커·상세·차트가 편의를 위해 이를 한 최신값으로 혼합하지 않도록 설계한다.

## 5. 채택·보류 판단과 추가 확인

먼저 Map 공용 작업면의 외곽·가용 높이·Weather 토큰 연결을 수용한다. 그 다음 기존 상세의 정보 순서를
특보·선택 시간의 값·이후 시간별 흐름 중심으로 정리하고, 필요시 기존 API 시간/요소 계약을 보완한다.
문서 조사만으로 native 앱 개발·새 플래너·주행 안전/건강 판정·다중 모델 평균값은 채택하지 않는다.

[W3C 타깃 크기](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)와
[초점 가림 방지](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum)를 참고해 작은 i·닫기·
시간 선택도 조작 가능해야 한다. 시각 크기와 터치 영역을 구별한다. 기상청/앱의 아이콘·이미지 권리는 별도이므로
화면 이미지를 그대로 자산으로 복사하지 않는다.

후속 구현 전 필요한 확인은 실제 배포 버전·PC/모바일 map stage 치수, provider별 정상 관측/발표/유효 시각,
시간 창의 결과 잘림·누락, 특보 지역/효력·source 선택, 관측점의 대표성, 공용 토큰 dark/hover/focus다.
기존 fixture UI 통과를 실제 운영 정상으로 간주하지 않고, 설계의 과제 수행 시나리오로 확인한다.
