# 전체 주소 수동 갱신 수용

## 현재 상태

검증 진행 중이다. 전체 완료와 완료 후 UI 수용은 아직 확정하지 않았다.
대상은 1,450개이며, 원천 위치 데이터와 현재 배포 이미지를 유지한다.
Dagster daemon은 계속 OFF다. 관리자 UI의 실제 수동 실행 요청으로 만든 cycle을
기존 code server에서 순차 처리하며 외부 제공자에 대한 중복 재실행을 피한다.

## 첫 배치의 결과 판정 복구

최초 native run은 SUCCESS였고 주소 50개를 저장했다. 검사기는 INFO 로그에서
결과를 찾았지만 운영 instance의 로그 수준 때문에 해당 로그를 얻지 못해 INCOMPLETE로 기록했다.
이 실패 기록은 그대로 보존했다. 제공자 실패나 저장 실패로 해석하지 않는다.

복구 검사는 최초 run의 SUCCESS, 동일 cycle, 현재 DB와 종료 감사의 일치,
원천 데이터 불변, 외부 대기열 불변 및 활성 worker 부재를 확인했다.
이미 저장한 50개를 재호출하지 않고 나머지 1,400개부터 계속했다.
후속 배치는 로그 문구 대신 native 상태와 DB의 유효 주소 증가·대기 건수 감소를 대조한다.

## 완료 판정 기준

- 전체 대상의 유효 주소 수, due=0, pending=0, failed=0, 수동 요청 및 진행 상태 해제
- 원천 위치 데이터 불변, 모든 실행의 native SUCCESS, 외부 대기열 불변, daemon OFF
- desktop/mobile에서 상태·최근 결과·수동 실행 가능 상태 확인
- 실제 호출 수와 계산한 상한을 구별

resolver 요청과 HTTP 요청의 정확한 횟수는 계측하지 않았다. 처리 건수 기반 resolver
요청 상한과 최대 3배 HTTP 상한만 기록한다. 최근 결과 50개의 UI 검사는 전체 DB 감사의
대체 증거가 아니다.

예약된 6개월 갱신, 센서 자동 실행, daemon을 통한 자동 복구 및 24시간 안정성은
이번 수동 cycle 수용 범위에 포함하지 않는다.
