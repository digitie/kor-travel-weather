# n150 운영 기록

이 문서는 `n150`에 배포할 때 사용하는 비밀값이 없는 운영 기록이다.

| 항목 | 값 |
| --- | --- |
| 호스트 | `digitie@192.168.1.14` |
| 프로젝트 경로 | `~/kor-travel-weather` |
| 데이터베이스 | PostgreSQL, `127.0.0.1:14100` |
| API | `192.168.1.14:14101` (LAN override) |
| Dagster | `192.168.1.14:14102` (LAN override) |
| admin web | `192.168.1.14:14105` (LAN override) |

운영 HTTPS 도메인은 다음과 같다.

| 서비스 | 운영 URL |
| --- | --- |
| API | `https://weather-api.digitie.mywire.org` |
| Dagster | `https://weather-dagster.digitie.mywire.org` |
| admin web | `https://weather.digitie.mywire.org` |

admin web Basic Auth 아이디는 `admin`으로 고정한다. 비밀번호는 배포 secret 파일에서
`WEATHER_UI_PASSWORD`로 주입하며 저장소에는 기록하지 않는다.

## 배포

원격 `~/kor-travel-weather/.env`는 모드 `600`으로 유지하고 Git에 추가하지 않는다.
비밀값은 password manager/secret manager에서 일회성으로 주입하고, 저장소 작업
복사본에는 평문 secret 파일을 남기지 않는다. KMA service key와 수집 target은
운영자가 발급·검토한 뒤에만 원격 secret store에서 주입한다.

```bash
# 예: 보호된 로컬 secret 파일을 사용한다(저장소 안에 만들지 않는다).
scp /secure/path/kor-travel-weather-n150.env digitie@192.168.1.14:~/kor-travel-weather/.env
ssh digitie@192.168.1.14 \
  'chmod 600 ~/kor-travel-weather/.env && cd ~/kor-travel-weather && \
   git fetch origin && git checkout main && git pull --ff-only && \
   docker compose --env-file .env \
     -f compose.yaml -f deploy/compose.n150.yaml up -d --build'
```

Compose는 `migrate` one-shot을 먼저 성공시킨 뒤 API/Dagster를 기동한다. 실패한
migration을 복구할 때는 원격 프로젝트에서 다음을 실행한다.

```bash
docker compose --env-file .env \
  -f compose.yaml -f deploy/compose.n150.yaml run --rm migrate
docker compose --env-file .env \
  -f compose.yaml -f deploy/compose.n150.yaml ps
docker compose --env-file .env \
  -f compose.yaml -f deploy/compose.n150.yaml exec -T db \
  sh -lc 'PGPASSWORD="$POSTGRES_PASSWORD" psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" \
  -Atc "select version_num from alembic_version"'
```

기본 Compose는 loopback에 바인딩한다. n150 override는 API/Dagster/web만
`192.168.1.14`에 바인딩해 외부 HAProxy가 접근할 수 있게 하며, DB는 loopback-only로
유지한다. n150 방화벽에서는 HAProxy source만 애플리케이션 포트에 허용하고, 이 포트를
인터넷에 직접 공개하지 않는다. override를 사용하지 않는 임시 확인에는 인증된 SSH
tunnel을 사용한다.

```bash
ssh -N \
  -L 14101:127.0.0.1:14101 \
  -L 14102:127.0.0.1:14102 \
  -L 14105:127.0.0.1:14105 \
  digitie@192.168.1.14
```

HAProxy upstream은 다음 주소를 사용한다.

```text
weather-api.digitie.mywire.org     -> 192.168.1.14:14101
weather-dagster.digitie.mywire.org -> 192.168.1.14:14102
weather.digitie.mywire.org         -> 192.168.1.14:14105
```

배포 후 `/health`, `/version`, admin token을 사용한 위치 조회, Dagster GraphQL
repository/schedule 상태를 확인한다. 외부 reverse proxy 도메인도 다음처럼 확인한다.

```bash
curl -fsS https://weather-api.digitie.mywire.org/health
curl -fsS https://weather-dagster.digitie.mywire.org/server_info
curl -u admin:'<WEATHER_UI_PASSWORD>' -fsS https://weather.digitie.mywire.org/
```

target과 KMA key가 비어 있는 기본 설정은
서비스 기동 smoke만 제공하며, 실제 날씨 수집은 운영 설정을 채운 뒤에 검증한다.
